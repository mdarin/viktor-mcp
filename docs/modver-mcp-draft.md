# Draft: modver-mcp — semver-детектор на базе bobg/modver

Статус: черновик (2026-10-05)
Источники: https://github.com/bobg/modver (v2, MIT), обсуждение семвера viktor.

## Идея

MCP-сервер на Go, который детерминированно определяет минимально необходимый
semver-bump по внесённым правкам — через библиотеку
`github.com/bobg/modver/v2` (не через CLI/shell-out).

modver сравнивает две версии Go-модуля (каталоги, git-коммиты, base/head PR)
и возвращает результат:

- `Major` — ломающие изменения публичного Go API (удаление/переименование
  типов, изменение сигнатур);
- `Minor` — добавления в публичный API (новые функции, поля структур);
- `Patchlevel` — остальное;
- `None` — без изменений.

Гарантия результата: если modver вернул `Minor`, patch-версии не хватит;
если `Major` — изменение точно ломающее. Это решение по коду, а не по
эвристике commit-сообщений.

## Предлагаемые инструменты

| Инструмент | Вход | Семантика |
|---|---|---|
| `modver_compare` | `old_dir`, `new_dir` | Сравнить два каталога с исходниками; вернуть bump + список изменений |
| `modver_revs` | `git_dir`, `old_rev`, `new_rev` | Сравнить две ревизии git-репо (теги, хэши, HEAD~1..HEAD) |
| `modver_last_tag` | `git_dir` | Сравнить HEAD с последним тегом → какой bump нужен для следующего релиза |
| `modver_pr` | `repo_url`, `pr_base`, `pr_head` | Base/head PR (опционально, можно позже) |

Ответ: `{bump: major|minor|patch|none, changes: [...]}` — изменения
пишутся в `io.Writer`, их стоит парсить/отдавать как текстовый trace.

## Реализация

- Стек: официальный MCP SDK на Go (как у viktor), stdio.
- API: `modver.Compare(oldDir, newDir, w)` → `Result`;
  `modver.CompareGit(gitDir, oldRev, newRev, w)`. Проверить точные сигнатуры
  на pkg.go.dev/github.com/bobg/modver/v2 при реализации.
- Перенять у viktor: instrument-обёртка (slog-логи + счётчики), graceful
  shutdown, конфиг.

## Ограничения modver (зафиксировать в README при реализации)

1. Видит ТОЛЬКО публичный Go API (экспортированные типы, сигнатуры, поля).
   Переименование приватного символа для него Patch.
2. Не видит поведенческие изменения (семантика ошибок, диапазоны входов) —
   сам modver предупреждает, что результат минимален; правило проекта:
   «результат modver — это НИЖНЯЯ граница bump».
3. Обе ревизии должны собираться; клон не-shallow (нужна история).
4. Для монорепо — сравнивать по модулю, не по всему репо.

## Особый случай: semver самого viktor

Для viktor публичная поверхность — не Go API, а MCP tool surface
(имена и схемы 83 инструментов, golden.json). modver этого не знает:
переименование tool-а он посчитает Patch, по факту это Major.

Поэтому для viktor нужен гибрид: bump = max(modver, surface-diff):

| Изменение golden.json | Вклад в bump |
|---|---|
| tool удалён или изменена схема входа/выхода | Major |
| добавлен новый tool | Minor |
| только description/docstring | Patch |

Правило «письменных расхождений» из ADR 0002 остаётся: любое отклонение
от автоматического вердикта фиксируется в трекере.
