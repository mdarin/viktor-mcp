# ADR 0002: Hard fork апстрима и политика дрейфа

Статус: принято (2026-10-05)

## Контекст

Виктор — порт [vikunja-mcp](https://github.com/ivantohelpyou/vikunja-mcp)
(Python, FastMCP). Апстрим — генерируемый из приватного репозитория код:
автор уже разом переименовал весь tool surface между версиями, история
коммитов не отражает эволюцию API. Классический fork с последующими merge
невозможен и не нужен.

## Решение

**Hard fork**: официальная точка отсчёта — **vikunja-mcp 0.9.3**
(PyPI, установленная в окружении пользователя; Python 3.12, FastMCP).
Дальше версии развиваются независимо: апстрим — референс семантики,
не источник патчей.

Базис зафиксирован в трёх местах:

1. этот ADR;
2. golden-снапшот tool surface (`internal/tools/testdata/golden.json`)
   — 83 инструмента, генерируется из зарегистрированных схем;
3. трекер `my-mcp/viktor` — карты переноса с семантикой каждого
   инструмента и найденными ловушками Vikunja v2.7.1 (ловушки собраны на 2.6.0 и перепроверены на 2.7.1).

## Политика расхождений

Любое отклонение от апстрима (переименование, другая схема входа, другой
код ответа) — допустимо, но осознанно:

- отклонение фиксируется в описании соответствующей карты трекера
  (что и почему отличается);
- намеренные улучшения (например, конкурентный `task_batch_get`,
  merge-семантика `task_update`) попадают в golden-снапшот и README;
- стабы («not implemented») остаются ровно на тех именах, где хендлер
  ещё не перенесён — имя и схема не дрейфуют молча.

## Чеклист регулярной сверки с апстримом

Раз в релизную итерацию (или при новой версии PyPI):

1. `uv tool upgrade vikunja-mcp` → сравнить `tools/list` апстрима с нашим
   `golden.json`: новые имена, удалённые, изменённые описания.
2. Для каждого нового инструмента апстрима — карта в трекере с решением
   «переносим / не переносим (почему)».
3. Сверить scoring-логику апстрима (`today_*` веса и деферы) с
   `internal/scoring/` — веса могут обновиться без смены tool surface.
4. Итог сверки — записать письменно (карта/комментарий), даже если
   решение «ничего не берём».

## Последствия

- Нет механического слияния апстрим-изменений; каждое — взвешенное.
- Дрейф сёрфейса в обе стороны ловят два теста: golden (`-update-snapshot`)
  и README-таблица (`-update-doc`).
- Пользовательская семантика вика может опережать апстрим (Go-first
  улучшения), это норма форка, а не регрессия.
